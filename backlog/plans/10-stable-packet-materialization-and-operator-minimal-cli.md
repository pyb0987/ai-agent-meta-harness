# Plan 10: Stable Packet Materialization and Operator-Minimal CLI

## Purpose

Turn the Plan 07-09 archive and active-pointer mechanics into a smaller routine
operator flow. Plan 10 owns the remaining usability gap: stable packet closure
should be generated by the checker and pointer writer wherever possible, not
hand-authored through YAML, hashes, provenance fields, or cleanup rules.

The target path for ordinary active work is:

```bash
governance start --base-ref <comparison-ref> --intent "..."
governance finalize --packet <packet> --base-ref <comparison-ref>
governance import-review --packet <packet> --from <review-artifact-or-stdin> [--output <artifact>]
governance write-pointer --packet <packet>
python3 scripts/verify-release.py --ci --base-ref <comparison-ref>
```

Humans should provide intent, review judgment, explicit exceptions, and residual
risk acceptance. The harness should infer requirements, generate durable
artifacts, bind hashes, refresh pointer-owned metadata, and explain only the
remaining human decisions. `import-review` is required only when inference or
policy requires durable review judgment; routine no-review changes should skip
that line without replacing it with hand-authored packet edits.

## Scope

In scope:

- Make stable closure materialization idempotent and checker-owned.
- Generate or refresh review-import artifacts, command artifacts, source refs,
  claim-evidence prompts, non-certifying placeholders, skip provenance, and
  pointer-owned replay metadata without requiring manual packet edits for
  routine active work.
- Add an import path for multi-review output that produces durable review
  artifacts and packet updates in one operation.
- Introduce a public `governance` CLI wrapper for routine commands while keeping
  repository-local scripts as implementation/debug entry points.
- Add a read-only archive/status view that reports active pointers, publication
  commits, packet ids, audit status, and blocking human decisions without
  becoming a trust ledger.
- Keep stable `check`, release, and pre-commit validation read-only except for
  explicit materialization commands.

Out of scope:

- Mandatory signed attestations or external runner identity.
- Durable archive refs as the required trust root.
- Historical command replay in routine release, pre-commit, `finalize`, or
  stable `check` paths.
- Prior-pointer whitelist semantics for future archive closure.
- New user-authored packet sections beyond `meta`, `input`, and `result`.
- A user-authored archive ledger or manual SHA registry.

## Slice 1: Stable Closure Materialization

`finalize` and `write-pointer` should distinguish between:

- machine-repairable instability, such as stale generated command artifacts,
  missing pointer-owned replay metadata, archive source refs, or review-import
  digest refreshes; and
- human decisions, such as missing review judgment, rejected residual risk,
  intentional skipped evidence, or non-routine waiver/downgrade acceptance.

Required behavior:

- `write-pointer` refreshes generated command artifact identities after packet
  bytes change, including post-review packet hash changes.
- `write-pointer --overwrite` is safe to rerun for the same packet and pointer
  output without manual cleanup.
- Stable closure generation fails closed when a required human judgment is
  absent, but the error names that judgment instead of exposing internal hash
  repair steps.
- Generated claim-evidence prompts and placeholders cannot certify stable
  handoff by shape alone. Runtime, proof-like, or public claims still require a
  raw artifact, imported review judgment, explicit skipped-evidence disposition,
  or residual-risk acceptance before stable publication.
- Plan 08 release/pre-commit evidence commands use a pointer-compatible evidence
  policy, including deterministic replay semantics for nondeterministic command
  streams.
- Plan 08 replay policy is stream-specific: content-bearing streams such as
  `verify-release.py --list` stdout must remain bound exactly or through a
  purpose-built semantic digest, while nondeterministic streams such as unittest
  timing stderr may be normalized only by command-specific rules that preserve
  the evidence claim being checked.

Acceptance seed:

- A harness-affecting active-gate change can reach pointer publication without
  hand-editing command artifact hashes or replay metadata.
- A generated claim-evidence placeholder leaves the packet non-stable until the
  claim is backed by raw evidence, imported judgment, skipped-evidence
  disposition, or accepted residual risk.
- A packet whose review import changes after `finalize` can still be published
  by rerunning `write-pointer`, provided all human judgments are present.
- Rerunning `write-pointer --overwrite` does not poison command artifacts or
  require deleting generated fields by hand.

## Slice 2: Review Import UX

Add a routine import path for multi-review results.

Target shape:

```bash
governance import-review --packet <packet> --from <review-artifact-or-stdin> [--output <artifact>]
```

Required behavior:

- Validate review target, packet id, packet hash, result digest, source digest,
  critic id, score, VETO, rerun status, blocking findings, why-not-10 text, and
  residual-risk disposition.
- Generate the review-import artifact under `archive/v2/artifacts/` and update
  the packet's judgment records.
- Reject stale, fake, wrong-target, wrong-category, or non-durable review
  imports.
- Preserve failed reviews and close them only through same-target reruns that
  meet the required score and VETO rules.

Acceptance seed:

- A multi-review artifact can be imported with one command and then pass stable
  packet validation without manual YAML stitching.
- The happy path either includes `import-review` when review judgment is
  required, or clearly reports that no review import is needed.
- If the packet requires a release-integration review, importing only a checker
  correctness review remains insufficient and produces a focused error.

## Slice 3: Public CLI Wrapper

Expose the routine lifecycle through a stable `governance` command.

Initial command set:

- `governance start`
- `governance finalize`
- `governance check`
- `governance write-pointer`
- `governance import-review`
- `governance status`

Required behavior:

- The wrapper delegates to existing repository-local implementations rather than
  duplicating checker logic.
- Documentation uses the public wrapper for the routine path and keeps
  `scripts/check-governance-acceptance.py` as a developer/debug entry point.
- `--base-ref` remains the stable handoff default; `--staged` remains preflight;
  `--worktree` remains exploratory unless explicitly marked non-stable.

Acceptance seed:

- New operator docs can explain active packet publication without exposing
  hidden staging rules, manual cleanup steps, or script-internal command names.
- Existing CI can continue to call repository-local scripts until the wrapper is
  wired into the release command list.

## Slice 4: Archive Status and Inventory

Add a read-only status view that makes the archive state understandable without
adding a new trust source.

Target shape:

```bash
governance status --base-ref <comparison-ref>
```

Required behavior:

- Report discovered active pointers, packet ids, publication commits,
  stable-handoff status, and historical audit status.
- Point to missing human decisions separately from generated artifact refreshes.
- Never whitelist archive paths or mark historical command artifacts as trusted
  evidence for future packets.

Acceptance seed:

- Operators can see why a release is blocked without checking out historical
  commits, manually resolving SHAs, or reading pointer internals.

## Deferred Decisions

- Whether public wrapper installation is a repository script, generated command,
  or package entry point.
- Which generated prompts or non-certifying placeholders are useful for routine
  claim evidence, and which claims must always require human-provided raw
  artifacts or imported judgment before stable handoff.
- Whether high-risk releases need optional signed runner attestation after the
  operator-minimal path is stable.
